Correct noise

Load the cross-source Step2 handoff, rename sample columns consistently, and apply replicate-aware zero/missing-value correction.

What the module does

Correct Noise is the first source-independent preprocessing module. It loads the active ProtVis_dataset whenever possible, shows the expression matrix and sample information, optionally normalizes sample-column names, and applies the replicate-aware correction rule.

The interface has three principal actions: Load data, Rename Columns, and Correct Noise.

Where Load data comes from

The current loader uses this priority:

  1. the active in-memory ProtVis_dataset;
  2. Step2_remove_unreliable_peptide.rda;
  3. Sage-specific compatibility snapshots such as Step2_sage_database_search.rda;
  4. older project-stage fallbacks when required for recovery.

Step2_remove_unreliable_peptide.rda is now the canonical data-source-independent Step2 checkpoint, even though its historical filename originated in the MaxQuant workflow. A successful Raw/Sage search publishes its completed ProtVis_dataset to this same handoff.

If the current object is still Sage_staging, the expression table is intentionally unavailable. Complete Search before running Correct Noise.

Replicate-aware correction rule

For datasets that use replicate suffixes _1, _2, and _3, ProtVis groups corresponding replicate columns and evaluates each protein within that group.

  • If at least two replicate measurements are non-zero, zero/missing cells are replaced using half of the sum of the non-zero replicate values.
  • If fewer than two non-zero replicates are present, the replicate-group values are set to zero and then converted to NA.
  • If no recognizable replicate suffixes exist, ProtVis returns the validated matrix without applying replicate-level correction.
  • Duplicate protein IDs are collapsed before the correction step, retaining the largest finite intensity per sample, to prevent many-to-many joins or reshaping from expanding the table.
Note

This behavior is intentionally different from a generic “more than half missing” filter or mean imputation. Missing-value imputation remains a separate downstream stage.

GUI workflow

The screenshot below shows the actual Correct Noise interface for the Sage-derived PXD065315 example. The red labels identify the recommended order.

Follow the numbered controls. 1. Load data. Open Pre-processing → Correct Noise and click Load data. Wait for the green Data loaded status, then inspect Sample info and Expression Matrix. Check that the expected sample columns are present and that the protein table is non-empty. The 5,209 rows visible in the screenshot are specific to this example run and are not a required target count for other datasets.

2. Rename Columns. Click Rename Columns. ProtVis uses maxquant_id mappings when they are available; otherwise already-valid sample_id names are retained. Inspect the Rename Columns result before continuing. For the illustrated Raw/Sage project, the intended columns are B73_C1, B73_C2, B73_C3, EA2024_C1, EA2024_C2, and EA2024_C3. Unexpected duplicate or unmatched sample names should be fixed before correction because replicate grouping depends on stable identifiers.

3. Correct Noise. Click Correct Noise. After a successful run, ProtVis switches to the Correct Noise result tab automatically. Compare the corrected table with the loaded expression matrix and verify that protein IDs, sample names, row count, zero values and newly introduced NA values are biologically and technically plausible.

Long-running actions use duplicate-run guards. A second rapid click on Load, Rename, or Correct Noise while the same operation is already running is ignored rather than executing it twice.

Outputs

The corrected matrix is written back into a new traceable ProtVis_dataset analysis state. ProtVis records the noise_correction result and process entry with the method replicate_correction.

For compatibility and recovery, the current implementation writes both:

Step2_remove_unreliable_peptide.rda
Step3_correct_noise.rda

Step2 is refreshed as the cross-source handoff, while Step3 remains the downstream compatibility snapshot.

Continue with Data transformation.

Troubleshooting

“No completed input stage was found.” Finish the previous input route first: run Sage Search for Raw data, MaxQuant Output Preparation for MaxQuant, or the appropriate parser/import for another source.

“The current ProtVis_dataset has no expression matrix.” The object is most likely a Raw/Sage staging project. Complete Search so Sage LFQ can create the protein matrix.

The corrected table looks empty although the action succeeded. Current ProtVis automatically selects the Correct Noise result tab after completion. If an older installation still behaves differently, reinstall the current dev version.

Working-directory errors after a restart. The module resolves the project directory from the shared workdir, dataset metadata, checkpoint metadata, Raw input directory, and finally the current R working directory. Keeping the project directory intact makes recovery more reliable.
