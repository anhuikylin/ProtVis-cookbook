RAW → mzML with MSConvert

Download and install ProteoWizard/MSConvert, convert vendor RAW files to mzML, and prepare validated inputs for the ProtVis Raw/Sage workflow.

Why this step is needed

ProtVis’s Raw workflow currently starts from .mzML + FASTA, whereas many mass spectrometers produce vendor-specific raw files such as Thermo Scientific .raw. Before Project init → Raw and Search (Sage), convert the vendor files to the open mzML format.

For Windows users, the recommended route is ProteoWizard MSConvert. ProteoWizard provides both the graphical MSConvertGUI application and the command-line msconvert.exe utility.

The complete route is:

Vendor RAW → ProteoWizard/MSConvert → mzML → ProtVis Project init → Sage Search → ProtVis_dataset

ImportantVendor RAW conversion is best performed on Windows

ProteoWizard can read and write open formats across platforms, but reading most vendor-specific formats depends on vendor libraries. The official ProteoWizard documentation recommends Windows for direct vendor-format conversion. For the Thermo .raw files used by the ProtVis example, perform conversion on Windows before moving the resulting .mzML files to Windows, Linux, or macOS for downstream analysis.

Download ProteoWizard / MSConvert

Use the official ProteoWizard download page:

  • ProteoWizard official download page
  • ProteoWizard user documentation
  • MSConvert documentation

On the download page:

  1. Select the ProteoWizard binary distribution for Windows.
  2. Prefer the current 64-bit Windows installer on a modern 64-bit Windows system.
  3. Read and accept the required license agreements for bundled vendor readers.
  4. Download the installer.

ProteoWizard is currently released as version 3.x, but the detailed build number changes frequently. For reproducibility, record the installed ProteoWizard/MSConvert version in your Methods or analysis notes rather than documenting only “MSConvert”.

Install on Windows

Run the downloaded installer and keep the default components unless your local IT policy requires another location. The current ProteoWizard download page states that the Windows installer requires Microsoft .NET Framework 4.7.2 or newer.

After installation, Windows should provide the ProteoWizard tools, including:

  • MSConvertGUI — graphical conversion interface;
  • msconvert.exe — command-line converter;
  • other ProteoWizard utilities such as SeeMS.

A typical installation is under a versioned ProteoWizard directory inside C:\Program Files\ProteoWizard\, although the exact path depends on the installed build. If several ProteoWizard versions are present, use the newest validated version consistently for a project.

Confirm the installation

Open Command Prompt or PowerShell, navigate to the ProteoWizard installation directory if necessary, and run:

msconvert.exe --help

If Windows cannot find msconvert.exe, either run it with its full path or add the ProteoWizard installation directory to your PATH.

You can also confirm the graphical installation by searching the Start menu for MSConvert or MSConvertGUI.

Recommended conversion with MSConvertGUI

For most ProtVis users, the graphical interface is the easiest route.

1. Start MSConvertGUI

Open MSConvertGUI from the Windows Start menu or from the ProteoWizard installation directory.

2. Add RAW files

Use Browse / Add to select one or more vendor RAW files. Batch conversion is recommended so that all samples are processed with exactly the same settings.

For the six-control-sample ProtVis example based on PXD065315, the source files are:

B73_C1.raw
B73_C2.raw
B73_C3.raw
EA2024_C1.raw
EA2024_C2.raw
EA2024_C3.raw

3. Select the output directory

Choose a clean output directory containing only the converted files for the current ProtVis project, for example:

E:\PXD065315\mzML\

Keeping vendor RAW and converted mzML in separate directories makes file validation and reproducibility easier.

4. Set the output format to mzML

Use:

Output format: mzML

mzML is ProteoWizard’s default open output format and is the format expected by the current ProtVis Raw/Sage workflow.

5. Use zlib compression

Enable zlib compression to reduce mzML file size without changing the underlying numerical spectra.

For general proteomics conversion, keep the default m/z precision unless you have a validated reason to reduce it. ProteoWizard currently defaults to 64-bit m/z encoding and 32-bit intensity encoding.

6. Add Peak Picking when the RAW file contains profile spectra

For profile-mode data that should be centroided before database search, add the Peak Picking filter and apply it to all MS levels:

peakPicking true 1-

When vendor centroiding is required, keep Peak Picking first in the filter list. ProteoWizard’s own msconvert documentation notes that vendor peak-picking algorithms operate on raw, untransformed data and therefore must be applied before other filters.

For typical Thermo proteomics RAW → Sage workflows, this is a practical default when the source data are profile-mode. If the instrument method already exported centroid spectra, do not apply redundant centroiding simply because the option exists.

WarningDo not add filters without a reason

Filters change the spectra passed to Sage. Avoid aggressive thresholding, scan removal, mass-window restriction, or other transformations unless they are part of a documented analysis plan. For a general ProtVis workflow, mzML output + zlib compression + appropriate centroiding is usually sufficient.

7. Start conversion

Click Start and wait until every file has completed without error.

The output should preserve the original filename stem:

B73_C1.raw     → B73_C1.mzML
B73_C2.raw     → B73_C2.mzML
EA2024_C1.raw  → EA2024_C1.mzML

This naming is important because ProtVis maps sample_info$mzml_file to the files in the selected mzML directory.

Command-line conversion with msconvert.exe

The command-line utility is convenient for scripted or repeated conversions.

Convert one RAW file

msconvert.exe "E:\RAW\B73_C1.raw" --mzML --zlib --filter "peakPicking true 1-" -o "E:\mzML"

Convert all RAW files in a directory

msconvert.exe "E:\RAW\*.raw" --mzML --zlib --filter "peakPicking true 1-" -o "E:\mzML"

The important options are:

Option Meaning
--mzML write mzML output; mzML is also the current default
--zlib compress binary arrays with zlib
--filter "peakPicking true 1-" centroid spectra at MS1 and higher levels when appropriate
-o set the output directory

For data that are already centroided, omit the peak-picking filter:

msconvert.exe "E:\RAW\*.raw" --mzML --zlib -o "E:\mzML"

To inspect the exact options supported by your installed build:

msconvert.exe --help
msconvert.exe --show-examples

Example: prepare PXD065315 for ProtVis

The built-in ProtVis Raw/Sage example uses six control samples from PXD065315. One reproducible layout is:

PXD065315_control/
├── raw/
│   ├── B73_C1.raw
│   ├── B73_C2.raw
│   ├── B73_C3.raw
│   ├── EA2024_C1.raw
│   ├── EA2024_C2.raw
│   └── EA2024_C3.raw
└── mzML/
    ├── B73_C1.mzML
    ├── B73_C2.mzML
    ├── B73_C3.mzML
    ├── EA2024_C1.mzML
    ├── EA2024_C2.mzML
    └── EA2024_C3.mzML

After conversion, point ProtVis → Project init → Raw/mzML input to the mzML directory, not the original raw directory.

Verify the converted files before ProtVis

Do not rely only on the .mzML extension. Confirm that:

  1. the number of mzML files equals the expected number of RAW files;
  2. each mzML file is non-empty and has a plausible file size;
  3. filenames match sample_info$mzml_file exactly;
  4. conversion completed without MSConvert errors;
  5. the files contain MS spectra and, for DDA proteomics, expected MS1/MS2 scans;
  6. the same conversion settings were used for every sample in the comparison.

If needed, ProteoWizard’s SeeMS can be used to open an mzML file and visually inspect spectra before database searching.

Connect the mzML files to ProtVis

Once conversion is complete:

  1. Open Project init.
  2. Select Raw as the data source.
  3. Load or upload sample information containing sample_id and mzml_file.
  4. Upload the matching protein FASTA.
  5. Select the directory containing the converted .mzML files.
  6. Click Check mzML files and resolve every Missing/Invalid row.
  7. Click Project init.
  8. Open Search and run Sage.

Continue with Raw/mzML + Sage search.

Troubleshooting

MSConvert cannot open the vendor RAW file. Perform vendor-format conversion on Windows and confirm that you installed a ProteoWizard build with the required vendor readers. Do not assume a native Linux build can read proprietary vendor data.

The mzML files are extremely large. Confirm that zlib compression is enabled. If the source is profile-mode and your downstream search requires centroided spectra, confirm that Peak Picking was applied appropriately.

Sage finds no spectra or very few PSMs. First verify that the mzML contains valid MS1/MS2 spectra and that centroiding was appropriate. Then check the FASTA, precursor/fragment tolerances, enzyme, modifications, and acquisition type.

ProtVis reports missing mzML files. The filename in sample_info$mzml_file must match the converted file name exactly, including the .mzML extension.

The conversion works on one sample but fails on others. Inspect the MSConvert log for the failing files and confirm that all source files were completely downloaded/copied and were acquired using a vendor format supported by your installed ProteoWizard build.

Reproducibility checklist

Record the following information with the project:

ProteoWizard/MSConvert version:
Operating system:
Original vendor format:
Output format: mzML
zlib compression: yes/no
Peak Picking: yes/no
Peak Picking MS levels:
Additional filters:
Conversion date:

Keeping these settings together with the original RAW files, converted mzML files, FASTA, Sage configuration, and ProtVis project directory makes the Raw → Sage workflow substantially easier to reproduce.
